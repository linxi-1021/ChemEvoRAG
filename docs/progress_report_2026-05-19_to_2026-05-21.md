## 二、遇到的问题及解决方案

### 问题 1：GitHub 网络不可达
**现象**：`pip install` 时 `git clone https://github.com/...` 连接被重置。  
**解决**：配置 `git config --global url."git@github.com:".insteadOf "https://github.com/"`，改用 SSH。

### 问题 2：NumPy 2.x 与 OpenCV/MolScribe 不兼容
**现象**：`import cv2` 报错 `AttributeError: _ARRAY_API not found`。  
**解决**：降级 NumPy：`pip install "numpy<2"`（最终版本 1.26.4）。

### 问题 3：transformers 版本冲突
**现象**：`chemrxnextractor` 依赖 `AdamW`，但 `transformers >= 5.0` 已移除。  
**解决**：降级 `transformers==4.36.2`，同时降级 `sentence-transformers==2.7.0` 以兼容。

### 问题 4：layoutparser EfficientDet Dropbox 链接失效
**现象**：`layoutparser` 的 `MODEL_CATALOG` 中 Dropbox URL 返回 404。  
**解决**：从替代源下载 4 个 EfficientDet 模型文件到本地；通过 `init_pdfparser(path)` 传入本地路径，绕过 Dropbox catalog。

### 问题 5：HuggingFace 下载超时/SSL 错误
**现象**：`hf_hub_download` 无法连接 `huggingface.co` 或 `hf-mirror.com`。
**解决**：实现全局 `hf_hub_download` 拦截——模块导入时自动检查 `data/models/`，文件存在则直接返回本地路径并复制到 HF 缓存，不发起网络请求。同步拦截 `snapshot_download`。

### 问题 6：RxnScribe/MolDetect 内部硬编码 HF 下载
**现象**：`RxnScribe.__init__()` 和 `MolDetect.__init__()` 内部调用 `self.get_molscribe()` → `hf_hub_download("yujieq/MolScribe", ...)` 写死。
**解决**：类级别 monkey-patch `rxnscribe.interface.RxnScribe.get_molscribe` 和 `MolDetect.get_molscribe`，指向本地 MolScribe 文件。必须在任何实例创建之前应用（`__init__` 中就会触发下载）。

### 问题 7：GPU CUDA OOM
**现象**：同时加载 7 个模型到 GPU 显存溢出。  
**解决**：`batch_size=1`，每个模型加载前 `torch.cuda.empty_cache()`，步骤 9 前 `del model` 释放显存。当前 CPU 已能稳定运行 100%。

### 问题 8：PyTorch 证书验证失败
**现象**：`download.pytorch.org` 的 SSL 证书在 Windows 上验证失败。  
**解决**：手动从浏览器下载 `resnet50-0676ba61.pth`（~98MB）到 `data/models/torch/hub/checkpoints/`。

### 问题 9：C 盘空间不足
**现象**：HF 缓存默认路径在 C 盘，模型下载撑满系统盘。  
**解决**：模块级设置 `HF_HOME` 和 `TORCH_HOME` 环境变量，指向项目内的 `data/models/huggingface/` 和 `data/models/torch/`。

### 问题 10：MolScribe confidence 值超出 [0,1]
**现象**：`MoleculeCard.confidence` 字段要求 `le=1.0`，但 MolScribe 返回原始 logit score（如 2011.0）。  
**解决**：`src/evidence/builder.py` 中 `_normalize_confidence` → 单候选且 [0,1] 内保留原值；多候选用 softmin 组内相对归一化（低分 → 高置信度）。
